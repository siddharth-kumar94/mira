# Features

Last verified: f064d7ee53a4 on 2026-10-20 (live)

Rally Features, under their own name. Two entry points: the workspace Features (`/projects`, opens on Timeline) and a team's Features (`/team/<id>/projects`, opens as a List). Each feature has a page (`/project/<key>`) with Overview, Activity and Stories tabs. Features are read-only apart from updates, comments and priority (D23, D38): there is no New feature button and no editing of dates, status, lead or name. PMs and team leads use it. It lives in `web/src/pm/`. Overall: beta. The list, board and feature page were driven live; guessed column widths, a no-summary layout gap and a burn-up that steps where Linear's curves keep every row below stable.

## How to get to it (user POV)

1. In the sidebar, under "Workspace", open "Features" for every feature of your teams (Timeline), or open a team's "Features" for that team's (List).
2. The round Display button switches List, Board and Timeline; the round Filter button narrows.
3. Click a feature to open its page. "Activity" holds updates and comments; "Stories" lists its stories across teams.

## Driving it

Preconditions: baseline, then `rallypoc seed` (the [DEMO] features).

- **projects-list**, **projects-board**, **projects-display**, **projects-pi**: → `rallypoc browser run projects` → PASS: List, Board then Timeline show the [DEMO] features and one overruns.
- **projects-page**, **projects-issues-tab**: → `rallypoc browser run project-across-teams` → PASS: the [DEMO] feature's Stories tab lists its [DEMO] stories under status groups.
- **projects-list**, **projects-pi**: → `rallypoc check api` → `api:projects-read`, `api:pi-chips` PASS.
- **projects-burnup**: → `rallypoc api GET "/api/burnup?project=<a [DEMO] project's key>" --expect 200` → one point per day from the planned start to today. No browser flow opens the sidebar chart yet.
- **projects-filter**: not driven. **projects-priority**: `api:pm-priority` SKIP, no field.

## Gotchas

- **The [DEMO] Features read "No status" and sit in Backlog.** The seed cannot start them: Rally's work rules demand Financial Work Type and Investment Category before a Feature can move to Current PI (`scripts/seed_demo.py` does not set a State).
- **Calculated health shows many features Off track.** On 2026-10-20, 152 of 269 features across the two teams were Off track, because they are past their target date (spec §17). That is Rally's data hygiene, not a bug.
- **The workspace list shows "Loading features…" for several seconds.** `GET /api/projects` took 2.9 s on 2026-10-20 (`web/src/pm/ProjectsView.tsx:41`), on top of the team loads the page also starts.
